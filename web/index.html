Quickstart in 30 Seconds

Zero configuration, zero overhead. Copy and run right away.

1. Installation 2. Create Secrets 3. Encrypt & Secure 4. In-Memory Run 5. Editing Secrets 6. Git Guard Hook 7. CI/CD & Automation

1. Installation

Install the env-secret-lock utility globally on your machine using npm:

npm install -g env-secret-lock

Alternatively, you can skip installation and run commands dynamically using npx:

npx env-secret-lock --help

2. Create Plaintext Secrets

Create a standard, plaintext .env file at the root of your Node/Python/Go project directory:

PORT=3000
DATABASE_URL=postgresql://db_user:password@localhost:5432/main
API_KEY=sk_live_51Ny8BzH...

Fill it with all your sensitive development keys, tokens, and database passwords just as you normally do.

3. Encrypt & Secure

Convert your plaintext credentials into a highly secure, authenticated binary metadata structure at rest:

secret-lock encrypt

You will be prompted securely to choose and confirm your Master Password. Once entered:

  1. A secure .env.enc file is created using AES-256-GCM authenticated encryption.
  2. You can now **delete the plaintext .env file** from your disk. Plaintext secrets no longer touch the drive!

🛡️ Note: We have automatically configured your local project's .gitignore to ensure plaintext .env is never accidentally pushed to GitHub.

4. In-Memory Runtime Injection

Boot your project with your secrets safely decrypted directly into memory on startup:

secret-lock run "node index.js"

You will be prompted to type in your **Master Password**. Once verified:

  • The CLI decrypts .env.enc inside memory.
  • Injects the key-value variables directly into process.env of your child process.
  • Launches your app. Plaintext secrets are never written to disk, protecting them from physical access theft.

5. How to Add or Edit Secrets

Need to add a new API key or change a password? Simply follow this secure loop:

  1. Decrypt the file: Run secret-lock decrypt and enter your master password.
  2. Edit your variables: Open the restored plaintext .env and make your edits.
  3. Re-encrypt: Run secret-lock encrypt and re-enter your password to update .env.enc.
  4. Delete the plaintext: Delete the raw .env from your disk to keep your machine safe.

6. Install Git-Guard Safety Protection

Prevent embarrassing secret leaks to GitHub. Install our automated Git blocker hook:

secret-lock hook install

If you or a teammate ever attempt to commit an unencrypted plaintext .env file, Git will instantly block the commit and output explicit instructions on how to secure it first.

💡 To remove the pre-commit protection at any time, run secret-lock hook uninstall.

7. CI/CD & Production Automation

In non-interactive environments (such as GitHub Actions, Docker, Vercel, Render, or Heroku) where you cannot type a password, simply export the master password as an environment variable:

export SECRET_LOCK_PASSWORD="your-master-password"
secret-lock run "npm start"

The CLI will automatically detect the variable, decrypt in memory, and bypass the interactive prompt.
